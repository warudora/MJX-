# MJX Rules Assistant / Cloudflare Workers AI

This Worker powers optional, source-linked AI answers for the official MJX seven regulations.
The static site still works **without** this Worker: it displays direct clause-search results instead.

## How it works

- Browser UI: `../rules-ai.html` + `../mjx-rule-ai.js` / CSS.
- Japanese authoritative source: `https://warudora.github.io/MJX-/regulations-full.html`.
- The Worker fetches the actual official source **server-side** on each cache cycle, extracts the article anchors and retrieves relevant excerpts.
- The Cloudflare Workers AI binding (`AI`) runs `@cf/google/gemma-4-26b-a4b-it` (with thinking disabled for concise outputs). Source links are generated by the Worker, never trusted from the model.
- A configured rate-limiter binding (`RULE_AI_LIMIT`) provides an approximate 12 requests/minute per client network address per Cloudflare location.
- Questions are processed only for responses. This repository does not persist chat history or embed credentials in public files.
- The UI falls back to plain clause search if the Worker is unavailable.

## Deployment (one-time Cloudflare account operation)

1. Ensure Cloudflare Workers and Workers AI are available on the intended account. Check Cloudflare pricing/quotas and configure spend limits before opening public access.
2. In a terminal with Node.js 22+, run:
   ```sh
   cd worker
   npm install
   npx wrangler login
   npx wrangler deploy
   ```
   Alternatively use Cloudflare's approved CI/CD deployment mechanism with account credentials stored as repository secrets. Never commit credentials.
3. Copy the **HTTPS root URL** of the deployed Worker (for example, an account-specific `*.workers.dev` URL).
4. Replace the empty string in `../mjx-rule-ai-config.js` with that HTTPS root URL, commit and publish it with the website.
5. Open `https://warudora.github.io/MJX-/rules-ai.html?lang=ja` and test Japanese/English questions, direct clause links, AI outage fallback, mobile layout, and rate limiting.

## Operational and security notes

- The Worker only allows browser requests from `https://warudora.github.io`. Requests from a different Origin receive 403. Origin checks are **not** authentication: use account-level budget caps, WAF rules, and Cloudflare Analytics for abuse monitoring.
- The built-in rate limiter is approximate and may throttle users sharing the same public address. Adjust `worker/wrangler.toml` as needed.
- If running the site on a different origin, update `SITE_ORIGIN` in `worker/index.js` only after verifying the new official domain.
- The Worker never accepts client-supplied excerpts, URL targets, or source identifiers. Generated explanations are *not* the authoritative rules; users must read the Japanese source and applicable MJX administrator notices.
- For privacy, do not ask people to enter account credentials or personal information. Cloudflare's own observability settings and retention must also be reviewed.
- If the rules page changes its DOM structure, the index validates the expected article count; failing closed is preferable to silently generating incorrect citations. Update the validation and tests when legitimate amendments change article counts.
- English responses are reference translations. The Japanese source takes precedence.
- Run `node ../scripts/check_mjx_rule_ai.mjs` from this directory to exercise retrieval and response safety tests without contacting Cloudflare AI.
